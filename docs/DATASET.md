# Dataset (Phase 1)

The AI model is trained on **JsVul**, a public dataset of JavaScript functions extracted from real vulnerability-fixing commits on GitHub. Phase 1 of the project (`preprocessing/`) turns the raw JsVul files into a clean, deduplicated, **repository-disjoint** train / validation / test split.

## Getting the data

The raw dataset and the processed JSONL files are larger than GitHub's 100 MB file limit, so they are **not stored in this repository**. Rebuild them exactly with:

```bash
bash scripts/fetch_dataset.sh
# = git clone https://github.com/jsvul/jsvul.git data/raw/tools/jsvul  (checkout 036c7f7)
#   npm install && npm run phase1
```

On Windows, run it from Git Bash, or run the three commands by hand.

## Pipeline (`npm run phase1` → `preprocessing/run_phase1.js`)

| Step | Script | What it does | Output |
|---|---|---|---|
| 0 | `inspect_schema.js` | Documents the JsVul JSON schema | `reports/jsvul_schema_report.md` |
| 1 | `inventory.js` | Counts files, organisations, projects, commit pairs, CWE/CVE coverage | `reports/dataset_inventory.{json,md}` |
| 2 | `normalize.js` | Extracts every function record; normalizes source (CRLF→LF, trailing whitespace, blank-line runs); SHA-256 hashes | `data/processed/jsvul_normalized.jsonl` |
| 3 | `validate_js.js` | Parses every function with @babel/parser; records successes and failures | `reports/javascript_validation_report.{json,md}` |
| 4+6 | `deduplicate.js` | Filters unusable records (< 10 characters); exact and normalized duplicate detection | `data/processed/jsvul_clean.jsonl`, `reports/cleaning_report.md`, `reports/duplicate_report.{json,md}` |
| 8 | `leakage_check.js` | MinHash / LSH near-duplicate and vulnerable/fixed pair analysis (sampled) | `reports/pair_integrity_report.md` |
| 9 | `split.js` | Repository-disjoint 80/10/10 split with a seeded PRNG (Mulberry32, seed 42); aborts if any repository appears in two splits | `data/processed/splits/{train,validation,test}.jsonl`, `split_manifest.json` |
| 10 | `statistics.js` | Label, CWE, CVE, node-type and length distributions per split | `reports/dataset_statistics.{json,md}` |

The JSON reports are kept in the repository (the UI reads `reports/dataset_statistics.json`). The Markdown reports are regenerated by the pipeline and are git-ignored.

### Repository-disjoint splits

| Split | Functions | Repositories | Vulnerable | Vulnerable % |
|---|---:|---:|---:|---:|
| Train | 17,621 | 917 | 1,567 | 8.9% |
| Validation | 2,194 | 108 | 229 | 10.4% |
| Test | 2,081 | 139 | 243 | 11.7% |

No repository appears in more than one split, so the model is always evaluated on projects it has never seen. This avoids the inflated scores caused by near-identical functions from the same project.

## Record format (`splits/*.jsonl`, one JSON object per line)

| Field | Meaning |
|---|---|
| `sample_id` | Stable hash id |
| `organisation`, `project`, `fix_commit_sha` | Provenance |
| `file_type` | `vuln` (before the fix) or `fix` (after) |
| `source_file`, `function_name`, `node_type`, `start_line`, `end_line` | Location |
| `label` | 1 = vulnerable function, 0 = benign |
| `original_source`, `normalized_source` | Code (the models train on `normalized_source`; inference applies the same normalization) |
| `cwe`, `cve`, `github` | Advisory metadata (CWE ids, CVE ids, GitHub advisory ids) |
| `pair_id`, `vuln_sha`, `commit_msg`, `publish_time` | Commit-pair and advisory context |
| `parse_success`, `is_filtered`, `is_raw_duplicate`, `is_norm_duplicate`, `split` | Phase 1 quality flags and assigned split |

## Known limitations
- Near-duplicate analysis was run on a 1,500-record sample, because a full pairwise comparison does not fit in memory. Vulnerable and fixed versions of the same function are near-identical by design, and the repository-disjoint split keeps such pairs inside one partition.
- Labels are at function level and come from fix commits, so some "vulnerable" functions are only partially responsible for the vulnerability.
- SecBench.js was planned as a benchmark but was not used. The real-world evaluation uses NodeGoat and DVNA instead (see [EVALUATION.md](EVALUATION.md)).
